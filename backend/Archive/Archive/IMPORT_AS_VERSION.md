# استيراد حزمة مشروع كإصدار جديد

> تطوير في الفرع `feature/in-app-file-preview`. لا يُدمج أو يُفعّل على الإنتاج
> قبل اختبار end-to-end بقاعدة بيانات وMinIO تجريبيين.

## طريقة الاستخدام

1. افتح «استيراد المشاريع»، وارفع الحزمة المشفرة (إن لزم) ثم نفذ التحقق.
2. افتح «إعداد الاستيراد» لحزمة **VERIFIED** تحتوي مشروعًا واحدًا بصيغة schema `1.0`.
3. يختار مدير النظام «إضافة الحزمة كإصدار جديد لمشروع موجود».
4. ابحث عن المشروع الهدف واختر أحدث إصدار معتمد أو مؤرشف أو مرفوض.
5. اربط معرفات الجهة ومستويات السرية وتصنيفات الملفات. إذا لم تتضمن ملفات الحزمة
   `category_id`، اختر فئة ملفات مركزية افتراضية **نشطة**.
6. يبدأ الاستيراد عبر `POST /api/v1/packages/{id}/import-as-version`
   وحقله `target_project_id`؛ راجع النتيجة في «الحالة» بعد اكتمال العملية.

## حماية الهوية والملفات

- يتطلب endpoint دور `system_admin`. لا يمكن للمستورد العادي تمرير
  `target_project_id` إلى `/import` لتجاوز هذه الصلاحية.
- يرفض الحزم متعددة المشاريع ومخططات schema الأخرى في وضع الإلحاق.
- يتطلب تطابق `organization_id` بعد الربط ورقم المشروع وسنته.
- لا يسمح بتغيير مستوى سرية المشروع أو إضافة ملفات بمستوى مخالف.
- يحتفظ `project_uid`، ويعين `previous_project_id` ويزيد `version_no`،
  ويورث اسم المشروع من الإصدار السابق. لا يغير سجل الإصدار القديم أو ملفاته.
- يستخدم قفلًا تشاؤميًا على الإصدار الحالي لمنع إنشاء إصدارين متنافسين.
- ينشئ الإصدار الجديد وروابط الملفات ضمن معاملة قاعدة بيانات مستقلة؛ فشل
  استيراد أي ملف يمنع حفظ إصدار جزئي، مع تنظيف الكائنات التي رفعت في المحاولة.
- لا يحذف كائنات أصبحت مرتبطة بسجلات محفوظة حتى إن فشل تحديث حالة العملية بعد الالتزام.
- ما زال ملف المصدر وملفات الحزمة بحاجة إلى اجتياز التحقق من التوقيع والتجزئات.
- يتطلب نوع الملف غير المصنف «فئة افتراضية» موجودة ونشطة لأن
  `project.files.category_id` غير قابل لأن يكون NULL.

## قيود وتشغيل آمن

- يظل التشغيل اختياريًا ويتطلب اختيارًا صريحًا من مدير النظام.
- لا تُنقل ملفات الإصدار القديم إلى الإصدار الجديد تلقائيًا؛ يضيف الاستيراد
  الملفات الواردة في الحزمة إلى إصدارها الجديد فقط.
- ليس هناك معالجة آلية لمحتويات MinIO اليتيمة الناتجة عن انقطاع سابق؛
  شغّل `migration-file-link-audit.sql` للقراءة فقط ثم افحص البيانات يدويًا.
- قبل الدمج، يجب اختبار ملفات فعلية وكلمة مرور صحيحة/خاطئة، التزامن، اختلاف الجهة
  أو الرقم أو السنة أو مستوى السرية، فشل MinIO، ومحاولات إعادة الاستيراد.
